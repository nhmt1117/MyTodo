# MyTodo

MyTodo 是一款基于 Electron 的本地个人待办应用。2.0 重新整理了首页、日历、任务编辑和提醒系统：任务只在统一编辑窗口中维护，日历专注查看时间分布，提醒根据优先级提前介入。

当前版本：**2.0.9**。目前主要面向 Windows x64；macOS 和 Linux 虽保留构建配置，但尚未完成发布验证。

## 安装与使用

普通用户下载 Release 中的 `MyTodo-Setup-2.0.9.exe`，按向导安装即可，不需要 Node.js 或 .NET。关闭主窗口后应用会留在系统托盘继续检查提醒；完全退出请在托盘菜单中选择“退出程序”。

安装界面使用 Windows WebView2 Runtime；Windows 11 和多数已更新的 Windows 10 设备通常已包含它，缺失时安装器会明确提示先安装该运行时。

主界面包含三个区域：

- **待办**：查看已逾期、今天、未来 7 天、全部和已归档任务；未来 7 天按具体日期分组，并支持搜索、排序、快捷完成和长列表回到顶部。
- **日历**：查看普通任务与循环任务的日期分布，点击日期后可从右侧日程打开、编辑或删除任务。
- **设置**：管理开机自启、每周起始日、每日摘要、每周概览、安静时段、数据位置和 Windows 自动更新。

单词悬浮功能仍保留在代码中，但 2.0 暂不提供界面入口。

## 2.0 功能

- 统一的新建/编辑任务窗口，支持普通任务和每日、每周、每月循环任务。
- 标题最多 80 字，备注最多 500 字；空标题使用表单内提示并保留编辑焦点。
- 新建任务可复制最近一次创建任务的标题、备注、日期、时间、优先级、类型和提醒设置。
- 高、中、低优先级自动匹配不同提醒强度，也可为单个任务选择轻提醒、标准提醒、强提醒或自定义节点。
- 每日任务摘要、每周 7 天概览和可配置的安静时段。
- 自定义应用内提醒窗，可选择右下角或横向紧凑的顶部居中显示；两种模式均使用不透明信息面板，并支持直接完成任务、延后 15 分钟、延后 1 小时、延后到次日 09:00，或跳过本次提醒；15 秒无操作时默认延后 15 分钟。
- 点击提醒窗的非按钮区域会打开 MyTodo，并直接显示对应任务详情。
- 未完成的一次性任务逾期后每天最多提醒一次；延后、安静时段和单任务关闭提醒仍然生效。
- 日历复用已加载任务数据，日期切换不会重复读取任务文件。
- 日历每日任务列表使用固定占位的铃铛标识提醒状态，长标题会在铃铛前自动省略。
- 任务归档、恢复、删除确认、搜索和多种排序方式。
- 本地 JSON 原子写入、自动备份、损坏恢复和旧版数据迁移。
- 双重数据损坏时进入只读保护并提示打开数据目录，避免空列表覆盖原文件。
- 数据目录可直接打开，并可导出同时包含当前状态和原始恢复文件的 JSON 备份。
- 应用采用单实例运行；重复启动只会恢复已有主窗口，不会产生重复提醒和并发写入。
- 设置页显示提醒调度器的真实运行状态；运行日志保留在本地数据目录中用于故障排查。
- 窗口尺寸、圆角、阴影、最大化/还原与应用图标适配。
- Windows 安装器显示已安装版本；相同版本无需重复安装，升级需要确认，并禁止安装更旧版本。
- Windows 安装版直接读取 GitHub 最新正式 Release 的更新资源，支持手动下载进度和确认后重启安装。

## 提醒规则

选择“自动推荐”时，优先级决定默认节点：

| 优先级 | 模式 | 提醒节点 |
| --- | --- | --- |
| 高 | 强提醒 | 提前 7 天、3 天、1 天、2 小时和截止时 |
| 中 | 标准提醒 | 提前 3 天、1 天和截止时 |
| 低 | 轻提醒 | 提前 1 天和截止时 |

为避免循环任务的节点互相重叠，每日循环只保留提前 2 小时和截止时；每周循环不使用提前 7 天节点。应用错过多个节点后再次启动，只补发当前最近的一个有效节点，不连续弹出历史节点。

提醒服务每 30 秒扫描未来 60 秒内的提醒节点，并将临近节点加入每秒校准的触发队列；相邻扫描窗口会重叠，避免提醒刚好落在两次扫描之间。应用必须保持运行或留在托盘中；完全退出后不会自行唤醒。安静时段内暂不显示提醒，离开安静时段后再检查尚未发送的有效节点。

## 数据位置

发布版默认将数据保存在安装目录同级的 `MyTodoData` 文件夹。例如：

- 应用：`C:\Users\<用户名>\AppData\Local\Programs\MyTodo\MyTodo.exe`
- 数据：`C:\Users\<用户名>\AppData\Local\Programs\MyTodoData`

主要文件：

- `todo-store.json`：任务、稳定 UUID、云端版本和提醒发送记录。
- `win-config.json`：窗口、摘要、安静时段和其他应用设置。
- `sync-outbox.json`：启用云同步后等待上传的本地变更和重试状态。
- `sync-account.json`：由 Windows 安全存储加密保护的同步账户与刷新凭据。
- 同名 `.bak` 文件：上一次有效写入的自动备份。

设置页可以打开或更改数据位置，也可以导出一个带时间戳的 JSON 备份。导出文件同时保存当前规范化任务与设置，以及不含账户密钥的原始恢复文件。切换数据位置时应用会先保存当前数据，再迁移任务、设置、加密同步账户和备份；目标位置已有 MyTodo 数据时不会直接覆盖。

## 多端同步开发状态

设置页的“多端同步”已接入第一阶段服务端协议。首次启用前会明确显示本地待办数量，只有点击“确认并上传”后才会创建账户和上传现有数据。刷新令牌与账户恢复密钥使用 Windows 安全存储加密，访问令牌只保留在内存中。

同步采用本地优先模式：新建、编辑和删除会先写入本地文件及持久化发件箱，再由后台上传并拉取增量变化。网络或服务端不可用时，本地待办与提醒照常工作，后台从 30 秒开始逐步延长重试间隔；用户也可以在设置页手动同步。当前开发地址默认为 `http://127.0.0.1:3100/api/v1`，正式发布多端功能前将切换到固定 HTTPS 服务。

如果任务主文件与 `.bak` 都无法读取，应用会进入只读保护并保留原文件，不允许新操作覆盖异常数据。启动时会明确提示，也可从“设置 → 数据存储”打开包含运行日志的数据目录。升级前建议先从托盘完全退出应用，再导出备份或复制整个数据目录。

开发模式或显式传入 `--user-data-dir` 时使用对应的隔离目录：

```bash
npm start -- --user-data-dir=D:/MyTodo-test-profile
```

## 开发

已验证的开发工具组合为 Node.js 24、npm 11、.NET SDK 8、Electron 44.1.1、electron-builder 26.15.3 和 electron-updater 6.8.9。请保留 `package-lock.json`。

Windows 安装依赖：

```bat
install.bat
```

脚本会显示 npm 下载进度、请求耗时以及 Electron 下载/验证状态。连续约 5 分钟没有任何新输出时，再检查网络、代理或目录权限。

启动开发版：

```bat
start.bat
```

运行完整检查：

```bash
npm run check
```

## 打包

Windows 构建：

```bat
build.bat
```

该脚本会依次执行语法检查和自动化测试、生成 HTML 安装界面与静默 NSIS 安装后端、生成更新元数据、比对 ASAR 内的源码与文档，并写入 `dist/SHA256SUMS.txt`。

构建会复用 `node_modules/electron/dist` 中已通过安装检查的 Electron 运行时，避免重复下载或解压同一版本。

也可分别运行：

```bash
npm run check
npm run build:win
npm run verify:release
```

启用自动更新的 Release 必须同时上传安装包、对应的 `.blockmap` 和 `latest.yml`，不要分发工作目录或测试数据。普通用户手动安装时只需下载 `.exe`；其余两个文件由已安装的 MyTodo 在后台检查和下载更新时自动使用。

## Windows 安装

安装器会识别已安装的 MyTodo 版本。同版本会提示无需重新安装，较新安装包会显示从当前版本升级到目标版本，较旧安装包会被直接阻止。点击安装或升级时会立即检查 MyTodo 是否仍在运行；程序未退出时不会开始写入文件，安装过程中也会阻止再次启动 MyTodo。

选择父目录后，安装器会确保最终路径以 `MyTodo` 目录结尾。例如选择 `D:\Software`，实际安装到 `D:\Software\MyTodo`。安装完成页可分别选择“启动 MyTodo”和“开机自动启动 MyTodo”；开机启动选项会同步到应用设置，之后仍可在“设置 → 通用”中修改。

## Windows 自动更新

自动更新仅在 Windows NSIS 安装版中启用；开发模式、便携版和非 Windows 平台不会连接更新服务。应用启动 30 秒后自动检查，之后每 6 小时检查一次，也可以在“设置 → 关于”中手动检查。发现版本后点击“下载并安装”即可；下载完成会自动关闭应用、沿用原安装目录并启动精简的升级安装器。升级安装器不再显示版本确认、目录选择和开机启动选项，只保留安装进度与完成页。

仓库内的 `.github/workflows/release-windows.yml` 会在推送与 `package.json` 版本一致的版本标签（例如 `v2.0.9`）后运行检查、构建 Windows 安装包并发布 Release；标签可以带 `v` 前缀。工作流会上传安装包、`.blockmap` 和 `latest.yml`，并写入面向用户的中文发布说明。

```text
.
├── build/installer.nsh        # 静默 NSIS 安装后端与卸载逻辑
├── installer-shell/           # HTML/WebView2 安装与应用内升级界面
├── main.js                    # Electron 启动入口
├── preload.js                 # 安全 IPC 桥
├── index.html                 # 主窗口
├── reminder.html              # 应用内提醒窗口
├── float.html                 # 暂停开放的单词悬浮窗
├── renderer/                  # 主窗口、提醒窗和悬浮窗界面逻辑
├── src/main/
│   ├── config.js              # 全局设置与窗口尺寸
│   ├── backup.js              # 用户数据导出备份
│   ├── dataLocation.js        # 数据目录与迁移
│   ├── installOptions.js      # 一次性同步安装器启动选项
│   ├── installLock.js         # 安装期间的应用启动保护
│   ├── logger.js              # 本地运行日志
│   ├── storage.js             # 原子写入和备份恢复
│   ├── supportTools.js        # 数据状态与用户自救工具
│   ├── syncAccount.js         # 系统加密的同步账户凭据
│   ├── syncManager.js         # 推送、拉取与自动重试
│   ├── syncOutbox.js          # 持久化本地变更队列
│   ├── todoStore.js           # 任务数据模型
│   ├── reminderScheduler.js   # 提醒与摘要调度
│   ├── updateManager.js       # Windows 安装版更新状态与下载
│   ├── windows.js             # Electron 窗口和托盘
│   └── ipc.js                 # 主进程接口
├── src/shared/recurrence.js   # 循环与提醒规则
├── .github/workflows/         # Windows Release 草稿构建
├── test/                      # 自动化测试
├── scripts/                   # 安装检查和发布校验
├── MyTodo.ico                 # Windows 多尺寸图标
└── assets/                    # 图标源稿与提醒音效（含来源说明）
```
